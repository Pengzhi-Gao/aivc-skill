# AIVC 执行手册

## 四阶段

1. 选择 KO/OE/药筛及结果类型。
2. 检查输入和模型契约。
3. 运行每个目标/药物条件并落盘原始结果。
4. 按 `downstream-results.md` 选择适用的默认图组，生成表格、图、质量记录和 report.md。

## 运行环境

各后端跑在各自隔离的解释器里，按 `backend-environments.md` 选环境，不要在主环境里跑
CellOracle。启动前先确认解释器路径和后端版本，并写进 `manifest`。

## 运行记录

每次运行保存：

```text
results/<run_id>/
  manifest.yaml
  provenance.json
  raw/
  tables/
  figures/               # 包含 figure_manifest.csv
  validation.json
  errors.jsonl
  report.md
```

批量药筛以 `(drug, dose, time, cell_type)` 为最小运行单元。已完成条件写入 checkpoint，失败条件写入 errors，不用空结果覆盖。

## 结果展示执行

1. 检查实际保存的输出是表达、网络、状态还是排名，并核对基线、单位、条件和覆盖范围。
2. 根据 `downstream-results.md` 的任务图组生成适用的主图和配套视图；有疾病参照、剂量、目标状态或实测数据时再启用相应扩展。
3. 每张图先保存源数值表和绘图参数，再绘图；不得从旧图片估算数值。图形失败只重画相关图，不重跑成功的模型条件。
4. 检查实际导出图的文字、轴、色标、图例、对照和源数据，登记 `figures/figure_manifest.csv`。
5. 缺少图形所需输入时登记 `skipped` 和原因；绘制失败登记 `failed`。二者均与模型预测的运行状态分开。

只读取或整理已有运行时，使用现有产物补图，不自动启动新的模型、疾病差异分析或实验。富集等下游计算按已授权范围和实际数据执行。

## 报告内容

`report.md` 只包含：

- 任务和后端
- 输入文件、预处理和参数
- 完成/跳过/失败条件
- 结果文件路径
- 按问题组织的结果图及各自源表，说明变量、单位和直接数值现象
- 图形清单，以及未生成的默认图及其原因
- 输出类型和单位
- 覆盖率、OOD、重复性或其他技术检查
- 未独立验证项目
- 未评估项目和原因

不自动撰写疾病机制、疗效、因果、靶点或实验优先级。

历史示例报告保留其原有完成状态；新增图组只有实际执行并查看导出文件后才写为完成。结果描述、质量检查和实测验证分别呈现。

## 失败状态

- `no_prediction`: 后端不覆盖目标
- `failed`: 运行报错
- `not_applicable`: 数据或任务不适用
- `partial`: 部分条件完成
- `unvalidated`: 结果已生成但无独立验证

保留可运行条件的原始结果。只有输入无法解释、后端无输出、结果完全退化或关键字段缺失时阻断对应条件。

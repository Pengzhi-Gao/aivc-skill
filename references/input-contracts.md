# AIVC 输入契约

开始新分析时，按 `SKILL.md` 的启动模板一次询问缺项：**分析数据、分析目录、运行环境、分析任务、模型、目标基因或药物库**。用户在当前任务中已指定的项直接沿用；可用文件、已安装模型及历史示例作为候选供选择。缺项时仅检查候选数据和环境，不启动推理或训练。只要求“测试一下”也不能自动补成示例分析；模型与数据不兼容时等待用户补数据或重选模型，不自动回退到其他路线。

## 启动必填项

| 字段 | 必须明确的内容 |
| --- | --- |
| `data_selection` | 用户选定的数据路径及每个文件的用途；固定背景后端则明确选择其自带基线与细胞系，疾病参照另列 |
| `analysis_dir` | 工作文件和结果的保存根目录，由用户指定 |
| `environment` | 用户指定的环境/解释器，或新建环境的安装位置；运行前记录解析后的实际解释器及版本，多个兼容环境需用户选择 |
| `task` | `ko`、`oe`、`drug` 中本次要执行的任务；多任务须分别明确 |
| `backend` | 用户选择且与任务兼容的模型 |
| `intervention` | KO/OE：基因 ID 或列表及逐个/联合运行方式；药筛：用户选定的药物库路径或明确的候选清单 |

把六项及其用户选择依据写入运行记录；从文件核实的物种、尺度、列名等元数据另记来源。六项齐全后继续检查模型所需输入，无需再索要通用启动确认。环境和分析目录沿用当前任务中已给出的路径，其余缺项继续补问。

代码、权重、词典、先验等模型资源由执行者按 [模型配置规则](model-setup.md) 获取或复用，并记录版本与路径。需要用户明确的是研究数据、任务和模型等分析选择；可按规则配置的公开资源由执行者完成。

## 通用字段

- `expression`: 表达矩阵或 AnnData 路径
- `matrix_type`: `raw_counts`、`normalized`、`log1p`
- `species`: 物种
- `gene_id`: symbol、Ensembl 或后端要求的 ID
- `cell_type`: scRNA 细胞类型字段（如有）
- `sample_id`、`donor_id`、`batch_id`: 样本/供体/批次字段（如有）
- `condition`: 未干预、疾病、对照或药物条件
- `baseline`: 未干预参考条件

疾病/对照仅在需要疾病差异或疾病方向比较时必需。单独运行虚拟干预响应时，使用未干预基线即可。

## KO

共同必填：用户指定的目标基因、未干预 scRNA、基因 ID；多个基因需明确分别敲除还是联合敲除，联合扰动还需核对模型支持。细胞类型/组织标签用于定群分析，是否必填按所选模型与比较问题核对。示例基因同样需要用户选定。

CellOracle 还需要：原始计数、与物种和 gene symbol 匹配的 TF-靶基因先验、可拟合的 GRN，以及目标基因在推断 GRN 中存在。参数化示例从所选数据计算 PCA/UMAP，`--group-col` 是描述分组，`--grn-unit-col` 用于指定分群 GRN；未提供时在全体细胞拟合一个 GRN。KO 将目标表达设为模型尺度上的 0。
Geneformer `delete` 示例限人类数据，需要：与所选权重/tokenizer 版本兼容的原始全转录组计数、`.var['ensembl_id']` 中无版本后缀的人类 Ensembl ID、`.obs['n_counts']` 每细胞原始计数总量和目标基因 token 覆盖；先编码为 Geneformer 数据集，再运行 in silico perturbation。该操作删除排序编码中的目标 token，结果以 embedding 影响记录。
GEARS 还需要：与目标细胞和扰动类型匹配的单细胞 KO/CRISPRi 训练数据。

单细胞网络/状态模型需要单细胞输入。将目标表达设为零后，需完成模型的扰动传播与输出检查，再记录 KO 模拟结果。

## OE

共同必填：用户指定的目标基因、未干预 scRNA、基因 ID；多个基因需明确分别过表达还是联合过表达，联合扰动还需核对模型支持。目标表达值仅对要求数值设定的模型必填，CellOracle 需用户指定目标值或分位数及依据；不自动沿用示例中的 OE 分位数。

CellOracle 还需要与 KO 相同的计数和 GRN 输入。其 target value 必须在 CellOracle 的 `imputed_count` 内部尺度（原始计数经 log1p 与 KNN 平滑）和数据范围内，记录设定依据；固定设定值低于部分细胞基线时，这些细胞在模拟中会下降，需单独报告。目标值和模拟结果均按模型内部表达尺度标注。
GEARS 还需要匹配的 CRISPRa/OE 单细胞训练数据。
Geneformer `overexpress` 示例使用与 KO 相同的人类原始全转录组计数、`.var['ensembl_id']`、`.obs['n_counts']`、目标 token 和版本匹配检查；只改变排序编码，结果为 embedding 影响，输入使用排序编码操作。字段来源见[官方 tokenizer 源码](https://huggingface.co/ctheodoris/Geneformer/blob/main/geneformer/tokenizer.py)。

## 药物筛选

按后端确定输入形态：外部基线模型需要表达矩阵与药物库；固定背景模型使用其自带对照；原生排名模型按其特征契约输入。

共同必填：用户选定的药物库文件路径或明确的候选药物清单、候选药物标识、目标细胞背景、后端需要的结构或表征。记录药物库来源/版本（未知时明确标记）、文件哈希、候选数和用户指定的筛选范围；历史 FDA 库作为候选供用户选择。用户只说“FDA 药物库”等名称但有多个版本时，列出候选来源供选择。PRnet/chemCPA 需要剂量及单位；UniPert-G2CP 无剂量输入，标 `not_applicable`。时间若是模型输入则必填，若由权重固定则记录固定值与来源，未知则记录 `unknown`，时间曲线需要已知的多个时间条件。

若做疾病方向比较，另需疾病/对照表达或可核对差异基因表。单细胞疾病差异优先按供体×细胞类型聚合后分析，避免把细胞数当生物学重复。

路由前先分清后端的基线来源：

- PRnet/chemCPA 的模型接口允许外部基线；当前权重是否适用另行检查。PRnet 的 LINCS 适配器使用自带配对对照，外部基线适配器直接调用前向接口。记录实际适配器、权重、基因顺序、预处理、协变量与 OOD 状态；患者样本与 A549 细胞系分别标注。
- 不接受外部基线的（UniPert-G2CP）：细胞背景固定在训练用的细胞系，只能变药物那一侧。结果明确标注模型自带细胞系基线，用户疾病参照另列。
- UniCure：基线先转成与 checkpoint 匹配的细胞表征；LINCS 示例需要 Uni-Mol 表征、剂量和有序 978 基因基线，见 [输入与代码](unicure-workflow.md)。
- DrugReflector：输入有方向的状态转换 v-score，疾病恢复为疾病 → 目标状态；候选药物先映射到 checkpoint 原生类别，输出排名。签名构造及覆盖处理见 [完整流程](drugreflector-workflow.md)。

模型输入按各自权重要求的基因顺序映射。区分实测零值、未测基因和 ID 映射失败；缺失不能统一填零。只有经该后端验证的缺失处理才可使用，并保存掩码与依据；否则停止依赖该输入的推理。评分和绘图取共同有效基因，缺测保留 NA。

做疾病方向比较前，先确认疾病参照与药物响应能落在同一套基因 ID 上并取到足够交集。Ensembl 与 gene symbol 混用时直接取交集可能为 0，此时不能算逆转分数，要先做 ID 映射并记录映射率。交集不足或没有合理评分尺度时跳过逆转评分。跨平台探索性方向比较需说明共同基因、效应定义与变换依据；匹配实测验证另行核对实验条件。具体计算前提统一见 `downstream-results.md`。

后端输出的是 gene symbol 还是 Ensembl ID、基因空间是 landmark 还是全转录组，都要在运行记录里写明。逐个记录药物候选的编码覆盖与训练集覆盖，两项分别核对。

无覆盖候选标记 `no_prediction`，预测值留缺失。部分后端在查不到药物表征时会**静默填零向量**，适配器需在运行前拦截。

## 缺口处理

缺少字段时：

1. 列出字段名和影响的任务。
2. 从用户选定的文件核实可读取的元数据并记录来源。
3. 将用户必须选择的缺项合并提问，提供候选或填写模板；已给出的内容不重复问。
4. 未补齐前不启动依赖该字段的推理或训练，也不自动用示例数据、其他模型或干预对象替代。

# AIVC 输入契约

## 通用字段

- `expression`: 表达矩阵或 AnnData 路径
- `matrix_type`: `raw_counts`、`normalized`、`log1p`
- `species`: 物种
- `gene_id`: symbol、Ensembl 或后端要求的 ID
- `cell_type`: scRNA 细胞类型字段（如有）
- `sample_id`、`donor_id`、`batch_id`: 样本/供体/批次字段（如有）
- `condition`: 未干预、疾病、对照或药物条件
- `baseline`: 未干预参考条件

疾病/对照仅在需要疾病差异或疾病方向比较时必需。单独运行虚拟干预响应时，使用未干预基线即可。

## KO

必填：目标基因、未干预 scRNA、细胞类型/组织、基因 ID。

CellOracle 还需要：TF-靶基因先验、可拟合的 GRN、目标基因在 GRN 中存在。
GEARS 还需要：与目标细胞和扰动类型匹配的单细胞 KO/CRISPRi 训练数据。

不允许：仅用 bulk 直接运行单细胞网络/状态模型；将表达矩阵置零当成已验证 KO。

## OE

必填：目标基因、未干预基线、目标表达值或模型条件码、表达尺度。

CellOracle 的 target value 必须在输入表达尺度和数据范围内。不能把模型尺度的数值自动称为实验倍数。
GEARS 还需要匹配的 CRISPRa/OE 单细胞训练数据。
Geneformer 的 `overexpress` 只改变排序编码，结果为 embedding 影响，不提供真实表达倍数。

## 药物筛选

输入形态是**用户的单细胞表达矩阵 + 一个药物库**。药物库每条记录至少要有药物标识和结构（SMILES），带剂量。

必填：目标细胞/组织、候选药物、药物 ID 或 SMILES、剂量、时间、细胞背景。

若做疾病方向比较，另需疾病/对照表达或可核对差异基因表。单细胞疾病差异优先按供体×细胞类型聚合后分析，避免把细胞数当生物学重复。

路由前先分清后端的基线来源：

- 接受外部基线的（PRnet、chemCPA）：单细胞矩阵可以直接当基线，但要做基因空间映射和尺度核对，覆盖率与量纲差异写进运行记录。
- 不接受外部基线的（UniPert-G2CP）：细胞背景固定在训练用的细胞系，只能变药物那一侧。若用户的样本癌种与该细胞系一致，可以在结果里说明，但不要写成"用用户的矩阵跑出来的"。

基因空间不一致时（例如 chemCPA 977 基因、PRnet/UniPert 978 基因），分别按各自空间映射，不要强行对齐。未覆盖基因置 0 并记录数量。

做疾病方向比较前，先确认疾病参照与药物响应能落在同一套基因 ID 上并取到足够交集。Ensembl 与 gene symbol 混用时直接取交集可能为 0，此时不能算逆转分数，要先做 ID 映射并记录映射率。交集过小、或疾病参照与药物响应的表达平台不同（如组织 bulk 对细胞系 landmark 签名）时，只报模型原生分数，不报逆转数值。

后端输出的是 gene symbol 还是 Ensembl ID、基因空间是 landmark 还是全转录组，都要在运行记录里写明。药物库还要确认每个候选是否真的被后端覆盖：能编码任意合法 SMILES 不等于该化合物在训练中见过。

无覆盖候选标记 `no_prediction`，不使用零向量补齐。注意部分后端在查不到药物表征时会**静默填零向量**，必须显式检查覆盖率。

## 缺口处理

缺少字段时：

1. 列出字段名和影响的任务。
2. 指出可从现有文件推断的字段，并标明推断。
3. 请求用户补充或提供可行的模板。
4. 未补齐前不启动依赖该字段的推理。

# AIVC-skill：虚拟敲除、过表达与药筛流程设计

> 本文为设计背景；执行规则以 `../SKILL.md` 和 `../references/` 为准。2026-10-10 起，预测状态、响应变化、评分区分度与独立验证分开记录，图形完成状态按实际导出文件登记。

## 目标与交付

AIVC-skill 引导用户从现有数据出发，选择虚拟敲除、虚拟过表达或药物筛选路线，完成模型运行、下游计算及结果交付。模型选型取决于数据类型、干预方式和所需输出；先保存模型原始结果，再记录技术质量检查。模型结果与独立验证状态分别登记；缺少独立实验时标注“未独立验证”，输入或运行异常时保存诊断记录。药物响应、基因干预和分子对接按各自原生定义交付。科学解释和是否采信结果由用户判断。

## 四阶段工作流程

1. **完成启动问答。** 按 `../SKILL.md` 核对数据、分析目录、运行环境、KO/OE/药筛任务、模型和目标基因或药物库；明确单目标还是批量目标，目标细胞/组织及想要的结果类型。KO/OE 区分“转录因子状态模拟”与“有干预训练数据的基因表达预测”；药筛区分“药物得分排名”与“每药逐基因响应”。
2. **盘点与补数据。** 检查 bulk/scRNA 数据、物种、基因 ID、样本/供体及批次、疾病/对照标签（仅疾病比较必需）；记录未干预基线。KO/OE 另查目标基因是否表达、是否为候选后端覆盖的调控因子、是否有匹配的 KO/CRISPRi 或 CRISPRa/OE 训练数据；药筛另查标准化分子结构、剂量和处理时间。缺必要数据时列出具体字段与可补来源，补齐后运行。
3. **选路线并运行。** 检查用户所选后端与数据粒度、扰动类型及输出要求的兼容性；记录输入处理、模型版本、参数与训练域。先保存每个目标/药物条件的原始输出，再进行覆盖率、无扰动或打乱条件及重复性检查。每个条件单独记录成功、跳过或失败原因。
4. **生成结果并交付。** 按模型实际输出生成完整表格与少量关键图；若另有疾病/对照数据且量纲可比，再计算疾病变化与干预变化的数值关系。交付“运行了什么、生成了哪些文件、哪些项目未能运行、质量检查是什么”。对接仅在用户选定药物并给出候选蛋白后启动独立流程。

### 运行状态与交付方式

| 情况           | 交付                     | 处理方式              |
| ------------ | ---------------------- | ---------------- |
| 运行成功，且有独立验证  | 原始结果、条件允许的后续计算、图表、验证指标 | 科学解释由用户完成         |
| 运行成功，但缺独立验证  | 同样保留数值结果与图表，标注“未独立验证”  | 验证状态单列    |
| 个别目标不覆盖/失败   | 已完成条件结果、未覆盖清单、错误原因     | 缺失预测留空       |
| 后端不可运行或不区分条件 | 输入与诊断记录、失败说明           | 按实际输出记录可用结果与诊断状态 |

保存**模型原生得分排名**，列明算法、输入背景和单位。网络、表达和排名分别使用对应结果类型；疾病方向比较需要可比的逐基因效应，条件不足时记录“未计算”及原因。疗效、因果关系和靶点确证需要相应实验或临床证据。

### 设计候选路线（接入状态见能力登记）

| 任务    | 可选模型路线                                                                               | 适合交付的原始结果                                                          | 必要前提                                                                         |
| ----- | ------------------------------------------------------------------------------------ | ------------------------------------------------------------------ | ---------------------------------------------------------------------------- |
| 虚拟 KO | **CellOracle**；有匹配 KO/CRISPRi 训练数据时可选 **GEARS**                                      | CellOracle：模拟表达层、网络传播和状态位移；GEARS：逐基因预测表达                           | CellOracle 需要 scRNA、TF-靶基因先验和目标调控因子；GEARS 需要带 KO/CRISPRi 标签的单细胞扰动数据          |
| 虚拟 OE | **CellOracle**；有匹配 CRISPRa/OE 训练数据时可选 **GEARS**；**Geneformer** 可做排序编码的 `overexpress` | CellOracle：模拟表达/状态位移；GEARS：逐基因预测；Geneformer：cell/gene embedding 变化 | CellOracle 的高表达值必须来自所用表达尺度和数据范围；GEARS 需 CRISPRa/OE 训练标签；Geneformer 使用排序编码干预 |
| 虚拟药筛  | **PRnet / UniCure**；DrugReflector 作为排名型后端                                            | PRnet/UniCure：逐药响应；DrugReflector：药物类别/得分/排名                        | 需匹配细胞、药物、剂量、时间和训练基因空间；覆盖不足单独标记                                               |

CellOracle 官方文档/源码明确提供 TF 扰动模拟：`perturb_condition={"Gene": 0.0}` 可做 KO，非负高表达值可作模型过表达输入，但必须检查数据范围和 OOD；结果主要是模拟表达层、`delta_X` 和细胞状态位移。Geneformer 官方 `InSilicoPerturber` 支持 `delete`、`overexpress` 等类型，通过改变基因排序编码输出 embedding 影响。GEARS 官方实现预测单细胞数据中的单基因/多基因转录响应，训练数据的细胞类型与扰动类型决定适用范围。

### 按手头数据决定能跑到哪里

| 用户数据                          | 可执行路线                                            | 无法直接生成的结果                         |
| ----------------------------- | ------------------------------------------------ | --------------------------------- |
| 仅有疾病/对照 bulk RNA-seq 和药物库     | 可建立疾病变化；筛药需另外取得对应细胞背景的实测药物响应或适用的药物预测后端及其必需输入     | 单细胞 KO/OE 和特定细胞类型的状态轨迹            |
| 有普通 scRNA、无真实干预数据             | 对网络覆盖的调控因子可评估 CellOracle KO/OE 模拟；若另有适用药物后端可运行药筛 | GEARS 另需匹配的扰动训练数据 |
| 有匹配细胞、带 KO/CRISPRi 标签的单细胞扰动数据 | 可评估训练与运行 GEARS KO；也可做 CellOracle 调控因子模拟          | OE 另需匹配的训练条件                    |
| 有匹配细胞、带 CRISPRa/OE 标签的单细胞扰动数据 | 可评估训练与运行 GEARS OE；也可做 CellOracle 调控因子模拟          | KO 另需匹配的训练条件                    |
| 仅有疾病/对照表达，无目标基因可用的网络或扰动模型     | 保留疾病差异结果并列出模型/数据缺口                               | KO/OE 待取得适用模型后运行                   |

每条路线均先尝试产出其**原生结果**；下游表和图只依赖实际存在的结果类型。候选部分失败时保留完成项，逐项列明失败原因。训练/下载公开数据或权重前核查版本、许可证、输入物种及细胞背景；用户指定模型时先检查是否真的支持该任务。

## 任务分支 A：虚拟基因敲除

### 必需输入与适用方法

- 指定目标基因、细胞类型/组织、未干预基线和希望得到的输出。疾病组与对照组仅在要求疾病相关比较时提供；没有疾病参照仍应完成可运行的 KO 模拟。单细胞基因调控网络需要相应单细胞数据。
- 用户选择 CellOracle 时：从单细胞表达和 TF-靶基因先验构建调控网络；只有目标基因在调控网络中、具备足够连接时，设目标表达为 0 并模拟细胞状态与下游表达变化。若要预测带真实基因编辑语义的逐基因响应，评估 GEARS 路线，但需要带 KO/CRISPRi 标签的单细胞干预训练数据。CellOracle 的表达变化和状态位移按模型模拟值记录。

### 下游模块与触发条件

1. **直接影响。** 输出目标基因、细胞群、基线表达、显著受影响基因/调控边及统计量、排序和多重检验信息（若方法提供）。图：Top 基因条形图；有全基因统计量才画扰动散点/火山图；只有具备逐基因干预前后表达量及有方向的变化时才画标准 MA 图。若仅有网络扰动幅度，画“基线表达—扰动幅度散点图”。横轴按后端实际定义标注，幅度与有符号变化分别展示。图中仅展示 Top N，完整表单独保存。
2. **功能与疾病数据比较。** 对有适用背景集的受影响基因做 GO/KEGG/Reactome 或预设通路富集；报告背景基因集、校正后显著性及上/下调口径。有方向的逐基因表达变化且用户提供疾病参照时，输出敲除效应与“疾病相对对照”变化的对应数值、散点图和通路表；无方向性或量纲不可比时只报告功能模块，标记“未计算疾病方向”。
3. **细胞状态。** 若有单细胞表达预测且模型能输出扰动后细胞状态，展示细胞类型/疾病相关程序分数变化；若有具备轨迹预测能力的单细胞后端且问题涉及发育/分化，再画扰动前后轨迹方向、细胞命运倾向。细胞比例、通讯和命运分析分别需要对应模型输出或实测数据。
4. **技术检查与结果交付。** 可获取真实 KO/CRISPR 或独立供体数据时，计算预测与实测逐基因方向、通路及无扰动基线的一致性；没有这些数据仍保留模型原始结果并标“未独立验证”。交付受影响基因/模块完整表和数据支持的图。

**交付建议：** `ko_targets.csv`、`ko_<gene>_effects.csv`、`ko_<gene>_pathways.csv`；按条件给 Top 基因图、通路点图；只有满足模型输出契约才给疾病变化对照图和轨迹图。

## 任务分支 B：虚拟基因过表达

### 必需输入与适用方法

- 指定目标基因、细胞/组织、基线表达、预期表达幅度/剂量、作用时间及用于校准的过表达数据（如可得）。先确认后端明确支持过表达，并说明干预值是绝对表达、相对倍数还是模型条件码。
- 用户选择 CellOracle 时：对其网络覆盖的调控因子，在所用表达尺度下设定高于基线、且落在数据可接受范围内的目标值；保存 `simulated_count`、`delta_X` 与细胞状态位移。若有标注过表达/CRISPRa 的单细胞训练数据，可用 GEARS 预测同类条件下逐基因响应，权重与 OE 扰动类型匹配。Geneformer 的 `overexpress` 只把该基因移动到排序编码前端，输出 embedding 变化，用于独立的表征影响分析。

### 下游模块与触发条件

1. **干预参数与覆盖。** 保存目标基因基线表达、设定表达值、实际进入模拟的值及可接受范围；有多个可运行条件时给每个条件的结果曲线。CellOracle 目标值按模型表达尺度标注；缺少可用目标值时先补齐参数再运行。
2. **直接影响与下游计算。** 后端输出逐基因变化时，交付每个目标的全量变化表、效应单位及模型定义的显著性口径；有对应统计量再绘 Top 基因、散点或热图，并按适用背景集做通路富集或模块评分。仅有 Geneformer 状态 embedding 时输出状态距离和排序；若疾病与干预逐基因方向可比，输出两者对应数值及图，解释交给用户。
3. **细胞与组织层面。** 只有具备可预测的细胞状态转移、轨迹或通讯输出，才展示疾病相关状态、分化倾向或细胞间信号。对于 CellChat 等依赖表达矩阵的方法，必须使用经验证的扰动后表达输入，并明确标注基线与扰动后来源。没有这些输出则标记“该项未评估”。
4. **KO/OE 条件对照。** 同一基因、同一细胞背景下若都成功运行，就给两种干预的逐条件结果并排图及差值，按实际结果展示方向。真实 OE 数据可用时另附目标表达与下游变化的对照指标；没有真实 OE 数据则标“未独立验证”，不阻断可运行的虚拟结果。

**交付建议：** `oe_<gene>_dose_manifest.csv`、`oe_<gene>_effects.csv`、`oe_<gene>_pathways.csv`；按条件给幅度曲线、Top 基因图、疾病基因变化对照图；轨迹/通讯图按后端能力可选。

## 任务分支 C：虚拟药物筛选

### 必需输入与两种后端

- 指定目标细胞/组织、候选药物清单，尽量提供标准化结构、剂量、处理时间及排除/纳入标准。若目标是按疾病变化筛药，还需疾病与对照数据或可核对的差异基因表；仅做给定药物的响应预测时，不强制疾病参照。疾病/对照差异分析需要样本级重复；单细胞分组检验应先按供体与细胞类型合并表达计数，再进行差异分析。
- **排名型后端**（例如 DrugReflector）：输入疾病相关转录变化，输出候选分子/类别或排序。逐药基因效应排序另需逐基因响应输出。
- **表达预测型后端**（例如 PRnet/UniCure，或匹配条件下的实测 LINCS 药物表达谱）：基因空间、剂量和细胞输入契约满足且模型正常输出时，保存每个药物的逐基因处理响应；独立验证情况另标注，不作为保存原始结果的前置条件。无覆盖分子标“无预测”，预测值留缺失。

### 下游模块与触发条件

1. **疾病参照。** 若提供疾病组和对照组表达数据，输出差异分析表、上/下调基因、通路及背景集，按统计单元绘制相应图；若用户已提供核实过的差异基因表，可直接导入并记录字段与来源。样本不足或混杂未处理时保留能完成的结果，记录样本量与混杂因素的影响。
2. **筛药主结果。** 逐药/逐剂量记录模型得分、算法名次、分子覆盖、细胞背景和分数定义；有方向性逐基因响应且用户提供疾病参照时，额外计算两者的对应数值，绘制算法排名、逐基因对照和剂量/跨样本图。表达预测后端另运行无药或打乱输入等技术对照；排名型后端运行其可支持的已知阳性、留出查询或重复性检查。缺独立验证只在结果中标记状态；若模型对真实/打乱条件无可辨差异，保存原生分数和诊断，排名区分度标为未通过。校准 Top 名次时不得只打乱药名与既有分数的对应关系，因为排序后分数集合不变。
3. **逐药基因结果。** 只要后端确实输出逐基因药物响应，就保存**每个药物**完整的基因效应排序表（基因 ID、方向、数值单位、剂量、细胞背景、预测/实测及验证标记）；按输出能力画表达热图、通路和不同条件一致性图。计算并保留扰动幅度，让用户分辨分数靠前但几乎无表达效应的药物。
4. **用户选择后的分子对接。** 由用户从算法结果中选择药物，并指定或确认候选蛋白来源；候选蛋白需有药靶或结构依据，可整理来源供用户选择。再准备配体/蛋白、选口袋、运行对接与已知复合物或阳性对照，交付构象、分数、参数、对照结果和失败记录。若无法取得可信结构/对照，仍交付已完成的药筛结果，单独标记对接未完成。

**交付建议：** `disease_gene_effects.csv`、`drug_ranking.csv`、`drug_<id>_gene_effects.csv`（仅逐基因后端）、`drug_<id>_pathways.csv`（有基因效应时）、`dose_sensitivity.csv`、`model_validation.csv`、`docking_inputs_and_scores.csv`（仅用户确认药物和蛋白、完成对接后）；图为排名、疾病-药物变化散点、通路点图、剂量稳定性以及有有效对照时的对接结构图。

## 质量检查与技术状态

- **输入可运行性：** 记录来源、样本/供体、批次、基因 ID 映射、分子结构和单位、训练域覆盖。缺关键输入则指出具体缺口并优先帮助补齐；该任务无法运行时，记录未完成状态及原因。
- **模型输出检查：** 对能输出干预前后表达的模型，记录同一背景的预测差值；对仅输出排名或网络变化的模型，保留其原生量纲。有无扰动、打乱条件、重复或真实实验时，计算对应检查指标并显示；未获得真实实验不阻止保存模型结果。
- **统计与可追溯性：** 差异表达及富集记录统计单元、背景集与多重检验；标明预测、实测、网络模拟、未独立验证。模型输出失败、完全退化或关键字段缺失时保存错误与诊断。
- **结果说明：** 解释数值定义、图形变量和直接观察，科学解释按本节的证据范围处理。

## 模型选型依据

- [CellOracle 官方文档](https://morris-lab.github.io/CellOracle.documentation/)与[官方源码](https://github.com/morris-lab/CellOracle/blob/a1c1bbff/celloracle/trajectory/oracle_core.py)：单细胞调控网络的基因扰动模拟；`simulate_shift` 接受指定目标表达值，可做表达设 0 与数据范围内的高表达模拟。TF 网络覆盖、输入表达尺度和状态位移输出需逐项目核对。
- [GEARS 官方仓库](https://github.com/snap-stanford/GEARS)：基于单细胞遗传扰动筛选数据预测单/多基因转录响应；官方明确不面向 bulk 或跨细胞类型泛化，故 KO/OE 路线都要分别核对训练数据的实际扰动类型。
- [Geneformer 官方虚拟扰动接口](https://geneformer.readthedocs.io/en/latest/geneformer.in_silico_perturber.html)：`delete` 与 `overexpress` 分别删除排序编码中的基因或将其移到前端；输出细胞/基因 embedding 变化。

技能包记录流程规则、后端能力、输入检查、模型前处理和结果整理步骤；模型实现与权重另行安装。每条路线完成真实数据或可复现示例的端到端测试后，才标记为已跑通。

## 执行约定

### 1. 先固定机器可读 manifest

每次运行只接受一个 manifest，至少包含：

```yaml
schema_version: "0.1"
task: "drug"                 # ko | oe | drug
backend: "prnet"             # 必须是 capabilities 中已注册后端
input:
  expression: "D:/data/control_counts.h5ad"
  matrix_type: "raw_counts"  # raw_counts | normalized | log1p
  species: "human"
  gene_id: "symbol"
  sample_id: "sample"
  donor_id: "donor"
  cell_type: "cell_type"
  condition: "condition"
intervention:
  targets: ["GENE1"]
  drugs: "D:/data/drugs.csv"
  dose_unit: "nM"
  doses: [10, 100]
  time_unit: "hour"
  times: [24]
model:
  weights: "D:/models/weights.pt"
  train_domain: "documented domain"
  seed: 42
output:
  directory: "D:/results/aivc_run_001"
```

按任务禁用无关字段并在运行前报错。没有 `manifest` 不启动推理。数据文件、权重文件和代码版本写入 `provenance.json`。

### 2. 规定 adapter 接口

每个后端 adapter 必须实现同一组动作：

```text
check_environment(manifest) -> environment_report
validate_input(manifest) -> input_report
run(manifest, checkpoint_dir) -> raw_outputs
normalize(raw_outputs) -> standardized_outputs
validate_outputs(standardized_outputs) -> validation_report
```

标准化结果按能力分别记录 `expression`（逐基因）、`state_embedding`（状态位移）、`ranking`（药物得分）或 `docking`（构象与打分），保留各类型的原生字段与量纲。共同元数据包括 `task`、`backend`、`condition`、`cell_type`、`source_type`、`effect_unit`、`ood_flag` 和 `seed`；异常逐项写入 `errors.jsonl`，保留其他已完成结果。

### 3. 统一结果目录与断点

```text
results/<run_id>/
  manifest.json
  provenance.json
  environment_report.json
  input_report.json
  validation.json
  report.md
  logs/run.log
  raw/<backend>/...
  tables/
  figures/
  checkpoints/completed.jsonl
  errors.jsonl
```

批量药筛每个 `(drug, dose, time, cell_type)` 独立写入 `completed.jsonl`；重启时跳过已完成且哈希一致的项。任何失败都保留错误、输入和后端版本。

### 4. 三条路线的 MVP 排期与验收

| 路线 | 候选后端 | 验收结果 | 输出边界 |
|---|---|---|---|
| 药物响应/筛选 | PRnet 或 UniCure | 已知药物/留出条件加载权重并产出非空逐基因响应；保存药物得分、响应表和覆盖率 | 逐项记录预测覆盖；对接按构象与分数交付 |
| 虚拟 KO | CellOracle；有匹配 KO/CRISPRi 训练数据时评估 GEARS | 小型 scRNA 示例跑通目标基因，产出逐基因或状态变化表、通路表及对应图 | 结果标注为单细胞网络模拟 |
| 虚拟 OE | CellOracle；有匹配 CRISPRa/OE 训练数据时评估 GEARS | 小型 scRNA 示例设定有数据依据的表达值，保存模拟值、逐基因/状态结果及范围检查 | OE 独立运行，目标值按模型表达尺度标注 |

每个 MVP 必须有一个 smoke test：固定小数据、固定权重/版本、固定 seed，执行完整命令并检查 `report.md`、`validation.json`、至少一个非空结果表和一张图；按实际测试结果登记可运行状态。

### 5. 必须提供的降级模式

- **缺后端/缺权重：** 生成 `failure_report.md`，列出可运行性缺口、需要的文件和准确接入命令。
- **候选部分覆盖：** 正常输出覆盖候选，逐项标记 `predicted` / `no_prediction` / `failed`，分别统计覆盖率。
- **仅有 bulk 数据：** 可运行疾病差异与排名型药筛；KO/OE 只在后端明确接受 bulk 且有校准证据时运行，否则返回方案和数据缺口。
- **独立验证缺失或未通过：** 保留可运行后端的原始得分、逐基因结果及诊断，并标明技术检查状态；若真实与打乱干预几乎没有区别，排名标为待解决。对接在用户选定药物与蛋白后独立运行。
- **输出不完整：** 报告列出缺失字段、受影响图表和未评估模块。

### 6. 路线验收

每条路线独立记录接入状态和端到端测试结果：未接入、已接入未测试、测试通过或测试失败。测试通过后再标记该路线可运行。实现顺序为药筛、CellOracle KO/OE，以及按训练数据条件接入 GEARS 或 Geneformer；每条路线更新模型能力、输入契约、运行示例和版本记录。
